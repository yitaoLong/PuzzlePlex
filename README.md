# PuzzlePlex 🧩


PuzzlePlex, a benchmark designed to assess reasoning and planning capabilities through a diverse set of puzzles. PuzzlePlex consists of 15 puzzles, including deterministic and stochastic games of varying difficulty, as well as single-player and two-player scenarios. The PuzzlePlex framework provides an environment for each game, and supports extensibility to generate more challenging instances as foundation models evolve. PuzzlePlex includes customized game-playing strategies for comparison.

--- 

## 📂 File Structure

Here's an overview of the main directories and their contents:

* **`puzzle/`**: Contains the environment for each of the 15 distinct puzzles. This includes:
    * Instance generators
    * State transition logic
    * Evaluation
    * Puzzles span single-player, two-player, deterministic, stochastic, text-based, and text-image modalities.
    * Each puzzle supports `easy` and `normal` difficulty levels.
* **`system/`**: The core framework that connects and manages interactions between puzzles and models.
* **`model/`**: Houses the model-specific code.
    * **`model/custom/`**: Contains customized methods and agents designed for specific puzzles.
    * **`model/llm/`**: Code of foundation models to each puzzle.
* **`prompts/`**: Includes all prompts used for interacting with models for each puzzle.
* **`instruction_based_results/`**: Stores all experimental results obtained from the instruction-based evaluation setting.
* **`result_code/`**: Contains the code solutions generated by models for each puzzle in the code-based setting.
* **`code_util/`**: Provides utility scripts for:
    * Post-processing generated code (e.g., extracting code blocks).
    * Identifying and managing missing Python packages for the environment.

## 🚀 Running PuzzlePlex

PuzzlePlex can be run in two primary settings: instruction-based and code-based.

### 🎮 Instruction-Based Setting

In this setting, models interpret instructions and play the puzzles directly.

1.  **Run the evaluation:**
    Execute the primary script using the command:
    ```bash
    bash run_instruction_based.sh
    ```
    This script calls `run_instruction_based.py`, which accepts several parameters to customize the run:

    * `puzzle_name: str`: The name of the puzzle you want to evaluate (e.g., `SudoKillPuzzle`).
    * `model_1: str`: The primary model being evaluated.
    * `model_2: str` (optional): The second model, used for two-player puzzles.
    * `num_players: int`: Number of players (either `1` or `2`).
    * `difficulty: str`: Puzzle difficulty (`easy` or `normal`).
    * `seed_range: str`: Range of random seeds for generating puzzle instances (e.g., `0-9`).
    * `one_shot: bool`: If `True`, uses one-shot prompting. (Currently supported for `SudoKill` and `TidyTower`).
    * `tot: bool`: If `True`, enables Tree-of-Thought prompting. (Currently supported for `SudoKill` and `TidyTower`).
    * `simplified_description: bool`: If `True`, provides the model with a simplified description of the puzzle rules.
    * `iterative: bool`: If `True`, the model plays iteratively. Default is `False` (model generates solution in one pass). Only used for `TidyTower` and `OptimalTouring`.
    * `legal_candidates: bool`: If `True`, provides the model with a list of legal next moves/actions. (Supported for `SudoKill` and `TidyTower`).
    * `with_history: bool`: If `True`, includes the history of previous moves as input to the model. (Supported for `SudoKill` and `TidyTower`).
    * `code_generation: bool`: If `True`, prompts the model to generate code as its solution. This is used for the code-based setting (see below).
    * `max_time_cost: float`: Maximum allowed time (in seconds) for running custom code or model-generated code. The game terminates if this limit is exceeded.
    * `max_new_tokens: int`: Maximum number of new tokens the model is allowed to generate.
    * `output_dir: str`: The directory where results will be saved.
    * `web: bool`: If `True`, launches a web simulator for better visualization of the gameplay.

### 💻 Code-Based Setting

This setting involves a two-step process: first generating code solutions, then running competitions between these generated solutions.

1.  **Generate Code Solutions:**
    Run the following script to have models generate code for each puzzle. This involves sampling 32 times per model for each puzzle.
    ```bash
    bash run_code_based.sh
    ```
    This script will call `run_code_based.py`, ensuring `code_generation=True` is set.

2.  **Run Code Competition:**
    Once code solutions are generated, use the following script to execute them and compare their performance:
    ```bash
    bash run_code_competition.sh
    ```

## 📊 Evaluating Results

After running experiments, use the evaluation script to process and analyze the results.

1.  **Run the evaluation script:**
    ```bash
    python3 evaluation.py --data_dir [results_directory] --eval-type [evaluation_type] --score-type [scoring_metric]
    ```

    For example,
    ```bash
    python3 evaluation.py --data_dir instruction_based_results --eval-type instruction --score-type "normalized score"
    ```

    **Parameters:**
    * `--data_dir`: Specifies the directory containing the results you want to evaluate.
    * `--eval-type`: Determines the type of results to evaluate.
        * `instruction`: For results from the instruction-based setting.
        * `code`: For results from the code-based setting.
    * `--score-type`: Defines the metric for evaluation.
        * `normalized_score`: Uses a normalized scoring system.
        * `elo_score`: Calculates Elo ratings for the models.
